# Теория: обработка на N вычислителях, секционное угловое БПФ, конвейер порций

> **Дата:** 2026-08-08 · **Статус:** теория, согласована в обсуждении. Кода нет и не предполагается.
> **Назначение:** свести в одну картину (а) концепцию апертуры `i×j` от 17.07,
> (б) физику потока с N приёмных каналов, (в) секционную раскладку углового БПФ на
> нативные матричные блоки, (г) конвейер порций. Отсюда — правки в формулу и главы.
>
> **Связанные документы:**
> `../00_КОНЦЕПЦИЯ_ixj_2n.md` — апертура `i×j`, каждая ось `2ⁿ`, zero-pad;
> `../glava3_dva_ffta.md` — два раздельных преобразования Фурье;
> `../glava2_trakt_priema.md` — тракт приёма;
> `../formula_izobreteniya.md` — С.1…С.11, У.1…У.8;
> `../bloki_ustroystva_20.md` — 20 блоков устройства;
> `rocm-2d-fft-context-for-claude.md` — исходная выжимка по потоку данных (иная терминология, см. §2).

## 1. Что здесь решается

Полная апертура даёт число каналов, при котором **и приёмный канал, и одиночный
вычислитель перестают справляться за такт**. Требуется:

1. вести приём **параллельно по нескольким каналам**, каждый — на свой вычислитель;
2. выполнять угловое преобразование **на нативных матричных блоках**, хотя размер
   оси апертуры многократно их превышает;
3. не платить за перераспределение данных между вычислителями больше, чем оно стоит.

Ниже показано, что все три задачи решаются **одним приёмом** — секционной раскладкой
и конвейером порций, — а число вычислителей становится параметром, а не отдельным
решением.

## 2. Терминология — приведена к патентной

В `rocm-2d-fft-context-for-claude.md` использована другая номенклатура (материал
готовился для внешнего исполнителя). Ниже — соответствие; **дальше по тексту и во
всех правках заявки используется только правая колонка**.

| Во внешнем документе | В патенте (канон) |
|---|---|
| `antenna = 512` | ось **X апертуры**, `i` |
| `range = 256` ⚠️ | ось **Y апертуры**, `j` — это **вторая угловая ось**, а не дальность; в исходнике названа ошибочно |
| `time = 5000 / 6000` | ось **быстрого (дечирпованного) времени**, `N`, переменна за такт |
| результат первого БПФ | **бин дальности** (после дечирпа частота биений = дальность) |
| `frame`, `rectangle` | **срез** — угловая карта `i×j` на одном бине дальности |
| `Kernel A`, FFT по 512 | первая ступень **углового** преобразования, ось X |
| `Kernel B`, FFT по 256 | вторая ступень углового преобразования, ось Y |
| `chunk = 50 frames` | **порция срезов** |
| `LDS` | память рабочей группы |
| `NIC`, сетевая карта | **приёмный канал** |
| `GPU` | **вычислитель** |

**Важное расхождение по порядку преобразований.** Во внешнем документе угловое 2D БПФ
берётся «на каждый отсчёт времени», то есть **до** дальностного. У нас порядок обратный
и он зафиксирован в `../glava3_dva_ffta.md` §3.2: **сначала глобальное дальностное
преобразование по оси быстрого времени, затем поячеечное угловое на каждом бине
дальности**. Оси разные, преобразования сепарабельны, поэтому результат тот же, но
описание ведём в патентном порядке — иначе главу 3 пришлось бы переписывать без нужды.

Обозначения из `../formula_izobreteniya.md` сохраняются: `Q` — число каналов (`Q = i·j`),
`N` — отсчётов после дечирпа, `L` — глубина объёмного участка.

## 3. Единая схема обработки

```
ПРИЁМ            N приёмных каналов, каждый в паре со своим вычислителем.
                 Каждому вычислителю достаётся СВОЯ ГРУППА КАНАЛОВ (подрешётка),
                 но ВСЯ ось быстрого времени.
                    │
СТУПЕНЬ 1        Дальностное преобразование Фурье — N независимых преобразований,
                 параллельно на всех вычислителях, поканально.
                 Обмена между вычислителями НЕТ: преобразование поканальное.
                    │
ПЕРЕРАСПРЕДЕЛЕНИЕ  Порциями по несколько десятков срезов (бинов дальности).
                 Чтобы построить срез i×j на бине r, нужны ВСЕ каналы этого бина,
                 а они лежат на разных вычислителях → передача обязательна.
                    │
СТУПЕНЬ 2        На каждом вычислителе — угловое 2D преобразование по своей порции
                 (секционная раскладка, §4) и СРАЗУ токенизация, не выходя из
                 памяти рабочей группы.
                    │
СБОР ТОКЕНОВ     Разреженная матрица токенов стекается на выделенный вычислитель.
                 Объём малый — передаётся быстро.
                    │
ВТОРОЙ ПРОХОД    Причинностный арбитр (блок 13) и рекуррентная сеть LSTM/GRU
                 (блок 14, пункты С.7 / У.4) — на этом же вычислителе.
```

Конвейер: пока над порцией `k` идут ступень 2 и токенизация, порция `k+1` **собирается
и передаётся одновременно**. Передача скрывается за вычислением.

**Ключевое свойство схемы:** угловое преобразование **никогда не разрезается между
вычислителями**. Срез `i×j` всегда собран целиком на одном вычислителе. Между
вычислителями делится только **набор срезов**. Поэтому обмена внутри преобразования
(«corner-turn») в схеме нет — есть одно перераспределение на естественном шве между
первым и вторым преобразованиями, который в С.1 уже заявлен как признак (а).

## 4. Правило выбора: нативная матричная операция или блочная раскладка

Достройка `../00_КОНЦЕПЦИЯ_ixj_2n.md`. Там сказано, что логическая апертура `i×j`
раскладывается плиточно на нативные блоки, а железо не трогается. Недоставало правила
**когда** раскладывать. Формулируется без указания типов устройств:

> Если размер оси апертуры **не превышает нативного размера матричной операции
> вычислителя** — угловое преобразование по этой оси выполняют **одной матричной
> операцией**.
> Если превышает — ось **раскладывают на нативные блоки с промежуточными
> поворачивающими множителями и вторым уровнем сложения**.

Раскладка алгоритмически точная: систематической ошибки склейка не вносит, разрешение
полной апертуры сохраняется (проверено численно в fp64,
см. `../../../MemoryBank/specs/fourstep_2dfft256_review_2026-07-16.md`: относительная
ошибка 8.9e-17, луч полной апертуры 0.39° против 7.18° у одиночной плитки, снятие
неоднозначности `k = k₁ + m·k₂`, где `m` — нативный размер блока).

> ⚠️ Оговорка о точности реализации: проверка выполнена в fp64. Матричные блоки
> работают на пониженной разрядности — реализация вносит свою ошибку квантования.
> Это свойство разрядности, а **не** секционирования, но оценивать её моделированием
> надо отдельно, до внесения численных утверждений в статью.

**Число уровней** определяется отношением размера оси к нативному размеру, и это надо
писать явно — иначе получается неверное впечатление, что двух уровней хватает всегда:

| Ось | Нативный размер | Раскладка | Уровней |
|---|---|---|---|
| 256 | 16 | 16 × 16 | 2 |
| 512 | 32 | 16 × 32 | 2 |
| 512 | 16 | 16 × 16 × 2 | 3 |
| ≤ нативного | — | одна матричная операция | 1 |

То есть на вычислителе с бо́льшим нативным размером ось 512 закрывается двумя уровнями,
на вычислителе с меньшим — тремя. Алгоритм один, меняется только глубина раскладки;
в формулу идёт правило, в описание — примеры.

Остаточный малый множитель (в примере ×2) выполняется обычной бабочкой и матричного
блока не требует: на глубину раскладки он влияет, на правило выбора — нет.

## 5. Конвейер порций — общий признак, а не признак «многокарточного» режима

Сбор данных для преобразования — самая дорогая операция схемы, дороже самого
преобразования. Поэтому:

> Обработку ведут **порциями по несколько десятков срезов**: пока над порцией `k`
> выполняются угловое преобразование и токенизация, порция `k+1` собирается и
> передаётся **одновременно**.
> Число вычислителей — **один или несколько**; при одном вычислителе перераспределение
> вырождается в локальную пересборку, **конвейер сохраняется**.

Правило выбора размера порции — адаптивное, без единой цифры:

> Размер порции выбирают так, чтобы **время передачи порции не превышало времени её
> обработки**.

Порция в несколько десятков срезов держит передачу крупноблочной (мелкие передачи
съедаются накладными расходами) и при этом в памяти вычислителя одновременно живут
только две порции. В описание — «в частности 50».

**Почему это один признак, а не два.** Заявлять конвейер отдельно для одного
вычислителя и отдельно для N — значит плодить пункты и объяснять эксперту, почему это
не два разных изобретения. Признак формулируется один раз на верхнем уровне, число
вычислителей — частный случай.

## 6. Масштабирование: одна конструкция во все стороны

| Режим | Апертура | Раскладка углового БПФ | Распределение | Обмен | Конвейер |
|---|---|---|---|---|---|
| АМ / ЧМ, малый квадрат | ≤ нативной | одна матричная операция | квадраты (кубы) розданы по вычислителям | **нет вообще** | **тот же** |
| Один вычислитель | любая | по правилу §4 | нет, локальная пересборка | нет | **тот же** |
| Полная апертура, N вычислителей | `i×j` большая | блочная, §4 | приём по подрешёткам, перераспределение по бинам | одно, на шве | **тот же** |

Инварианты во всех трёх режимах — **конвейер порций** и **токен**. Всё остальное
параметры. Это и есть заявляемое масштабирование.

Отдельно про АМ/ЧМ: там кубы нарезаются заданной длительности **с перекрытием**, разной
глубины (`../formula_izobreteniya.md`, С.9 и С.11). Если квадрат апертуры не превышает
нативного размера, куб целиком принадлежит одному вычислителю → **межпроцессорного
обмена для преобразования нет**, каждый вычислитель ведёт свои кубы от начала до конца:
преобразование, признаки, токен.

> Скрытое условие, соблюдаемое при конфигурировании: **границы квадратов согласованы с
> разбиением приёма по подрешёткам** — квадрат не должен пересекать границу групп
> каналов двух вычислителей, иначе обмен появляется снова.

## 7. Сокращение объёма перераспределения

Перераспределение — единственная цена распределённой схемы. Сократить его можно, но
**механизмы неравноценны, и это надо признавать в описании честно**, иначе на
моделировании вылезет отказ обнаружения.

Гейт работает **по оси дальности**: решается, строить срез на данном бине или пропустить.
**Каждый строящийся срез — всегда полный `i×j`**, урезанных апертур в схеме нет.
Копирование гейт не отменяет — он сокращает только **число бинов**, для которых оно
выполняется.

### Механизм 1 — детерминированное окно (надёжный)

После дечирпа `f_b = μ·2R/c`: рабочий интервал дальностей отображается в **ограниченную
полосу частот биений**. Всё, что вне полосы, лежит вне зоны ответственности и
отбрасывается **геометрически, без всякого решения об обнаружении**. Риска пропустить
цель нет. Работает **при любой помеховой обстановке**, включая заградительную.

Аналог в АМ/ЧМ-тракте — заданные границы нарезки кубов.

> ⚠️ Требует моделирования: окно защищает от того, что вне интервала дальностей, но не
> от помех внутри него. Насколько оно реально сокращает объём — зависит от того, во
> сколько раз оцифрованная полоса шире рабочего окна.

### Механизм 2 — межтактовая область интереса (уже заявлен)

С.11: «*участок, пустой в предыдущем такте, пропускают; участок, где отклика долго не
было, обрабатывают участком увеличенной глубины*». Плюс целеуказание от блока 1 и
матрица токенов предыдущего такта.

Это **лучший якорь для единства изобретения**: признак не изобретается заново, он
распространяется с уже заявленного объёмного примитива на распределённый ЛЧМ-тракт.

> ⚠️ **Риск, признанный явно:** новая цель или всплеск, которых в предыдущем такте не
> было, могут быть пропущены.
> **Страховка — перекрёстная, между трактами:** АМ/ЧМ-тракт берёт **большое окно** и
> ловит такой всплеск, даже если область интереса ЛЧМ-тракта его не покрывала. То есть
> быстрый и рискованный гейт одного тракта подстрахован широким захватом другого. Это
> самостоятельный довод в пользу совместной работы трактов и его стоит вынести в
> описание.

### Механизм 3 — энергетический предпросмотр (вспомогательный)

Каждый вычислитель считает по **своим** каналам некогерентную сумму мощности на бине
`E_k(r) = Σ|X_a(r)|²`. Обмен такими числами — по одному скаляру на бин на вычислитель,
объём ничтожный. После обмена полная `E(r) = Σ_k E_k(r)` известна всем.

> ⚠️ **Два ограничения, из-за которых механизм НЕ несущий:**
>
> 1. `E(r)` — сумма **некогерентная**. Угловое преобразование складывает каналы
>    **когерентно**, и весь выигрыш апертуры даёт именно оно. Некогерентная сумма
>    выигрывает лишь как корень из числа каналов, то есть **чувствительность
>    предпросмотра принципиально ниже** чувствительности после формирования луча.
>    Слабая цель, проявляющаяся только после углового преобразования, предпросмотром
>    **не видна**. Порог поэтому ставится **консервативно**: задача — отбросить
>    гарантированно пустое, а не «оставить обнаружения».
> 2. Под **заградительной помехой ось дальности заполнена целиком**, порог адаптивен от
>    шума → гейт пропускает всё и **вырождается**. А это ровно тот сценарий, ради
>    которого пишется заявка.

### Порядок применения

**1 → 2 → 3.** Первый безусловен, второй — основной рабочий со страховкой от АМ/ЧМ,
третий — уточняющий, самоотключающийся под заградкой.

### Общий принцип — он объединяет три оси и держит единство

Один замысел — **«полный объём не обрабатывается, обрабатывается отобранное»** — уже
воплощён в заявке на двух осях и здесь достраивается третьей:

| Ось отбора | Где | Статус |
|---|---|---|
| по **глубине куба** (грубый проход → отбор ярких → тонкий добор тех же участков) | АМ-тракт, С.9 | **заявлено** |
| по **межтактовой памяти** (пустой в предыдущем такте — пропускают) | С.11 | **заявлено** |
| по **оси дальности** (какие бины вообще перераспределять) | распределённый ЛЧМ-тракт | **новое** |

Это не три изобретения, а один принцип на трёх осях.

## 8. Как делить бины дальности между вычислителями

**Как лежат данные после ступени 1.** На вычислителе — массив `[канал][бин]`, бины
непрерывны (дальностное преобразование шло по быстрому времени, а оно непрерывно на
канал). Чтобы отдать порцию подряд идущих бинов, источник читает на каждый свой канал
**непрерывный кусок**, затем переходит к следующему каналу: регулярная двумерная выборка
с постоянным шагом.

Заложены **два варианта**, окончательный выбор — после обсуждения.

### Вариант «непрерывный раздел»

Все бины делятся на N непрерывных частей; каждый вычислитель набирает свою часть
порциями.

**За:**
1. **Источник читает последовательно** — соседние порции одного получателя лежат встык,
   шаг чтения постоянен на всю передачу.
2. **Получатель пишет непрерывно** — порция ложится встык к предыдущей, ступень 2 читает
   сплошной участок, матрица токенов вычислителя тоже получается сплошной, её проще
   собрать на выделенном вычислителе.
3. **Расписание статическое** — кто кому что шлёт, считается один раз на такт.
4. Обмен распадается на `N·(N−1)` **крупных** передач, а не на россыпь мелких.

**Против:** при сосредоточенной сцене (цели в узком интервале дальностей) вся работа
падает на один вычислитель, остальные простаивают.

### Вариант «карусель»

Вычислители забирают порции по очереди, чередуясь.

**За:** работа размазывается ровно независимо от расположения целей.
**Против:** соседние порции одного получателя отстоят на `N·(размер порции)` бинов →
поток чтения на источнике рваный; расписание вращающееся, а при включённом гейте (число
живых бинов меняется) ещё и плавающее.

### Предложение, снимающее противоречие

> Делить не **номера** бинов на N частей, а **список подлежащих обработке** бинов на N
> частей **равной длины**.

После гейта есть упорядоченный по возрастанию список живых бинов. Режем его на N равных
по количеству кусков. Живые бины идут по возрастанию → чтение на источнике **остаётся
последовательным**; у каждого вычислителя **поровну работы** независимо от того, как
цели распределены по дальности. Признак простой и прямо вытекает из гейта.

> **Статус:** заложены оба варианта плюс это предложение. Решение — после обсуждения.

## 9. Проекция на формулу и блоки устройства

### Способ

| Признак | Куда | Статус |
|---|---|---|
| Приём по N каналам; первое (дальностное) преобразование — **N параллельных преобразований по группам каналов**; по их завершении — перераспределение порциями перед вторым (угловым) преобразованием, с совмещением передачи и счёта | новый зависимый **от С.1** | новое |
| Правило «ось ≤ нативной → одна матричная операция; иначе блочная раскладка с промежуточными множителями и вторым уровнем» | дополнение **С.8** | новое |
| Ограничение объёма перераспределения по механизмам §7 | новый зависимый, опирается на **С.11** | частично заявлено |

Формулировка привязана к С.1 намеренно: перераспределение ставится на шов **после
завершения N параллельных первых преобразований, перед вторым**, и это не произвол —
единственное место, где обмен возможен без разрезания самого преобразования. Признак
**выводится** из уже заявленной структуры способа, а не пристраивается сбоку.

### Устройство

| Блок | Было | Становится |
|---|---|---|
| **3** — запись данных | «приём по оптическому каналу **через сетевую карту**», массив `Q·l` последовательно по антеннам | **N приёмных каналов, каждый в паре со своим вычислителем**; канал конструктивно сопряжён со своим вычислителем (непосредственный интерфейс, общий узел памяти); каждый канал принимает **свою подрешётку**; запись — сразу в память своего вычислителя, минуя общий буфер управляющей машины |
| **9** — угловое 2D БПФ | двумерное угловое преобразование на бине | дополняется **блочной раскладкой по правилу §4** |
| **4** — управление потоком | задаёт интерфейс, размеры и позиции | получает функцию **арбитража перераспределения**: нарезка порций, расписание обмена, применение гейта |
| **новый** — перераспределитель | — | сбор срезов порциями со всех вычислителей, конвейерное совмещение передачи и счёта |
| **13**, **14** — арбитр и LSTM/GRU | описаны функционально | физически размещаются на **выделенном вычислителе**, куда стекается разреженная матрица токенов |

> Уточнение к более раннему черновику: **отдельного блока «межсекционной склейки» не
> нужно**. Второй уровень раскладки (§4) выполняется **внутри одного вычислителя**, так
> как срез не разрезается между вычислителями. Склейка — часть блока 9, а не новый блок.

## 10. Отстройка от уровня техники

**Опасность.** Распределённое БПФ с перераспределением между узлами — плотно занятая
область (десятилетия высокопроизводительных вычислений: разбиения slab/pencil,
библиотеки распределённого БПФ). Пункт вида «*вычисления выполняют на N параллельных
вычислителях, данные распределяют между ними*» — это **самостоятельное решение из
области параллельных вычислений**, никак не связанное с распознаванием цели на фоне
ретранслятора. Эксперт вправе указать на нарушение единства изобретения и потребовать
выделения, а по существу — побить признак уровнем техники.

**Как отстраиваемся — три отличия, все опираются на уже заявленное:**

1. **Место обмена не выбрано, а выведено.** Перераспределение стоит на шве между двумя
   раздельными преобразованиями Фурье — признак (а) в С.1. В распределённом БПФ общего
   назначения обмен стоит **внутри** преобразования и разрезает его; у нас
   преобразование не разрезается никогда.
2. **Объём обмена зависит от данных.** В распределённом БПФ общего назначения обмен
   всегда полный и слепой. У нас он гейтируется — по детерминированному окну, по
   межтактовой области интереса (С.11) и по энергетическому предпросмотру.
3. **Обмен второго уровня — не данные, а токены.** На выделенный вычислитель уходит
   разреженная матрица токенов, а не куб. Это прямое следствие признака (б) С.1
   (токен вместо полной угловой карты), применённое к межпроцессорной шине.

## 11. Заметка реализации (не для формулы)

Ограничение размерности сетки запуска. При числе каналов порядка `i·j` нельзя класть это
число на ту ось сетки, которая ограничена: на нашем каноне запуск с числом каналов по
оси `Y` падал с ошибкой недопустимого аргумента.

- **Проверено:** запуск падал, ошибка воспроизводилась (зафиксировано в
  `DSP-GPU/MemoryBank/prompts/prompt_grid_axis_help_2026-07-23.md`).
- **Не сверено, данные расходятся:** по нашей заметке 2026-07-23 ограничены `Y` и `Z`
  (по 65535), велика `X` (порядка 2³¹−1); по устной памяти — ограничены `X` и `Y`,
  велика `Z`. Ни одна из версий отдельной проверкой не подтверждена → перед реализацией
  снять фактические пределы запросом свойств устройства, не полагаться ни на одну запись.
- **Предварительный вывод (тоже не подтверждён замером):** число каналов кладут на
  неограниченную ось либо обходят шагом сетки по ограниченной оси, сохраняя непрерывность
  доступа по оси отсчётов.

В патент и статью это не идёт — типы устройств и их ограничения там не указываются.
Заметка нужна разработчику.

## 12. Открытые вопросы и что моделировать

1. **Механизм 1** — насколько реально сокращает объём: зависит от того, во сколько раз
   оцифрованная полоса шире рабочего окна дальностей. Требует моделирования, и отдельно
   — поведение при помехах **внутри** окна.
2. **Механизм 2** — количественно оценить риск пропуска нового всплеска и достаточность
   страховки широким окном АМ/ЧМ-тракта.
3. **Механизм 3** — смоделировать потерю чувствительности предпросмотра относительно
   когерентной обработки и подобрать консервативный порог.
4. **Деление бинов** (§8) — выбрать между непрерывным разделом, каруселью и делением по
   списку живых бинов. Заложены все три.
5. **Размер порции** — правило «время передачи ≤ времени обработки» задано; конкретное
   число подбирается на железе.
